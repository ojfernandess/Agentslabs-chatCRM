## Motivo

Fase 3 unificou o planner; o `TurnToolScheduler` ainda importava `checkin/` (Embratur, payload assembly) e aplicava gates paralelos (`hasCompleteEmbraturFields`, regex tool-name).

## Decisão

**Scheduler v2** — Plan + CapabilityGraph + Facts only:

```
UnifiedExecutionPlan.pendingTools
  → orderToolsByFactDeps (CapabilityGraph)
  → schedulerPreExecBlockReason (TurnPolicy + canInvokeTool)
  → resolveSchemaToolArgs (SchemaArgResolver + config.eil)
```

**Componentes:**
- `scheduler/SchemaArgResolver.ts` — args via `argAliases`, `nestedGroups`, capability profiles
- `scheduler/TurnToolScheduler.ts` — zero imports `checkin/`
- `engine/ToolRegistry.ts` — `resolveStableToolName`, `byAlias` map (P-011)
- `ToolEilConfig` extendido — `stableName`, `argDefaults`, `argAliases`, `nestedGroups`

**Gate único:** `schedulerPreExecBlockReason()` = TurnPolicy + `capabilityPreExecBlockReason` + `canInvokeTool`.

## Patches endereçados

P-001, P-004, P-011, P-020–P-025, P-040–P-041 (parcial — runtime invoke path mantém checkin até Fase 7)

## Critérios de saída

- [x] Scheduler não importa `checkin/`
- [x] Agente fictício CRM passa scheduler
- [x] `TurnToolScheduler.test.ts` + `SchemaArgResolver.test.ts` verdes
- [ ] Scan: embratur hits ↓ no scheduler (CI)
