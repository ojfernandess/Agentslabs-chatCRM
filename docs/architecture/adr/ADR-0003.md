# ADR-0003: Unified Execution Spine — Prompt → IR → Runtime

| Campo | Valor |
|-------|-------|
| **Data** | 2026-07-30 |
| **Autor** | OpenNexo Platform — Arquitetura Principal |
| **Versão** | 1.0.0 |
| **Branch** | main |
| **Commit** | pending |
| **Componente** | Runtime / Execution Engine |
| **Status** | accepted |
| **Categorias** | Architecture, Runtime, Planner, Prompt Compiler, Scheduler |

## Motivo

O OpenNexo AI Runtime evoluiu com patches específicos por agente/playbook, tornando o comportamento imprevisível e impedindo a criação de novos agentes apenas via Prompt.

## Problema

1. **Dual runtime** — `agentNativeLlm.ts` (~3 861 linhas) bypassa `ExecutionEngine` em produção openconduit.
2. **47 patches catalogados** — 28 específicos de hotel/Embratur/tools (ver PATCH-REGISTRY).
3. **Prompt interpretado repetidamente** — Compiler, Planner e Validators duplicam parsing.
4. **LLM decide demais** — tool selection, workflow e fallback compensados por Synthesizer/Supervisor.
5. **MCP confirma** — execuções não emitem eventos `engine_*`; Reply Synthesizer força Modelo S1.

## Causa raiz

Evolução incremental por correção pontual (IF/guardrail/fallback) sem spine arquitectural único.
Componentes genéricos existem (`ExecutionEngine`, `PromptCompiler`, EIL) mas não governam produção.

## Alternativas analisadas

| Alternativa | Prós | Contras |
|-------------|------|---------|
| A. Continuar patches em `agentNativeLlm` | Rápido por agente | Escala impossível; regressões cruzadas |
| B. Reescrever runtime do zero | Clean slate | Risco alto; quebra compatibilidade |
| **C. Unificar spine existente + Prompt IR** | Reutiliza 166 ficheiros agent-engine; compatível | Esforço médio (~6 meses) |
| D. Mover lógica para LangGraph only | Graph visual | Não resolve acoplamento prompt |

## Alternativa escolhida

**C — Unified Execution Spine com Prompt IR formal.**

## Arquitetura antes

```
Prompt (texto) ──► agentNativeLlm.ts (monolito)
                      ├── patches Embratur/hotel inline
                      ├── TurnToolScheduler (parcial)
                      ├── ReplySynthesizer (compensação S1-S10)
                      └── LLM (decide tools + workflow)

ExecutionEngine.ts ──► deprecated / não usado em openconduit
```

## Arquitetura depois

```
Prompt
  ↓
Prompt Compiler ──► Prompt IR (versioned)
  ↓
Intent Analyzer
  ↓
Execution Planner ──► Execution Plan (DAG)
  ↓
Execution Contract + Capability Graph + Facts Engine + Policy Engine
  ↓
Tool Scheduler
  ↓
Workflow Runtime
  ↓
Execution Engine (único spine)
  ↓
LLM (raciocínio + args + reply apenas)
  ↓
Supervisor (Contract/Plan/Facts only)
  ↓
Workflow Validator (estrutural only)
  ↓
Audit Engine
```

`agentNativeLlm.ts` reduzido a **LLM adapter** (call + streaming + token accounting).

## Justificativa técnica

- **Prompt IR** elimina duplicação de parsers (`requiredToolNamesParser`, `turnPolicyParser`, `playbookRuntimePolicy`).
- **ExecutionEngine** já implementa `beginTurn()`, timeline, metrics, recovery — falta wiring.
- **EIL** (CapabilityGraph, FactsEngine, PolicyEngine) já existe — falta ser fonte única de verdade.
- **Compatibilidade** — playbooks existentes compilam para IR equivalente sem alteração de texto.
- **AGS** — toda fase gera ADR/RCA; MCP audita regressões.

## Riscos

| Risco | Mitigação |
|-------|-----------|
| Regressão S1–S10 hotel | Golden tests (126+) + MCP shadow mode Fase 2 |
| Playbook legacy não compila | Adapter PromptContract → PromptIR |
| Scope creep (novos patches) | AGS gates + PATCH-REGISTRY + lint CI Fase 8 |

## Rollback

1. Feature flag `AGENT_ENGINE_UNIFIED_SPINE=false` restaura monolito.
2. Prompt IR adapter bypass — runtime usa `PromptContract` directo.
3. Patches em `checkin/` permanecem até Fase 7 — rollback por fase.
