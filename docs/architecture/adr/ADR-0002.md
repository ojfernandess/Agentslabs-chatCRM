## Motivo

Check-in Embratur falhava silenciosamente quando campos de país/cidade não vinham de domínios FNRH válidos; o runtime activava conclusão prematura e o LLM contornava o Scheduler.

## Problema

Após ficha Embratur com EUA/Nova Iorque, `__completionReady` activava sem 6 campos completos; Scheduler bloqueava check-in mas LLM invocava `audaar_check_in` directamente; HTTP 200 com `validationError` era tratado como sucesso.

## Causa raiz

Catálogo estático IBGE para países estrangeiros; `sessionToolOutcomes` marcava completion sem validar Embratur completo; `toolOutcomeParsing` não detectava `validationError` em body HTTP 200; bypass hybrid LLM→tool sem guardas runtime.

## Justificativa técnica

Resolver `bgstdscpais`/`bgstdscpaisdest` via tool `embratur-reference` (domínios FNRH); guardas runtime globais; `__completionReady` só com 6 campos; `turnPolicyParser` omite check-in do catálogo LLM se incompleto; `validationError` → `ok:false`; gate em `agentNativeLlm` antes de check-in.

## Rollback

Revert commit `92dda4d`; desactivar `embraturRuntimeGuards` e restaurar `sessionToolOutcomes` anterior.
