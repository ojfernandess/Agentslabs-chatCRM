# ADR-0011: Architecture CI Gates

| Campo | Valor |
|-------|-------|
| **Data** | 2026-07-31 |

| **Versão** | 1.0.0 |
| **Componente** | Architecture Governance / CI |
| **Status** | accepted |

## Motivo

Fases 0–7 reconstruíram o Execution Engine; sem gates automáticos, patches prompt-specific regressam via PR. AGS Fase 1 tinha API programática mas faltava integração CI/pre-commit.

## Decisão

**Pre-commit** (`.husky/pre-commit`) → `architecture-pre-commit.mjs` → `runPreCommitArchitectureGate()` em ficheiros staged.

**CI workflow** (`.github/workflows/architecture-gates.yml`):
- Regression + generalization tests
- `scan-runtime-patches.mjs --fail-on-new`
- `architecture-ci-gate.mjs` (simulator + gates)

**ESLint rule** `eslint-rules/no-prompt-specific-patches.js` — bloqueia `if (toolName === "check_in")`, `prompt.includes()`, `botId` branches.

**Architecture Simulator** (`architecture-governance/simulator.ts`) — cenários vet + hotel pre-merge.

**Langfuse** — layer `architecture_governance` + `buildArchitectureGovernanceSpan()`.

**ciGate.ts** — unifica impact analysis, quality gates, score ≥7, patch scan, simulator.

## Gates bloqueantes (merge)

1. Impact analysis em ficheiros alterados
2. Quality gates AGS
3. Architecture Score ≥ 7 (≥ 5 pre-commit)
4. Zero novos hits `scan-runtime-patches --fail-on-new`
5. Zero patterns proibidos em ficheiros do PR
6. Architecture simulator verde
7. Regression suite (golden + generalization)
